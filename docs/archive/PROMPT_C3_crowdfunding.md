# PROMPT_C3_crowdfunding — クラファン挑戦と浅層探索（Phase C-3）

対象: ClaudeCode
前提: **C-2（ダンジョン基盤改修）完了後に着手すること。** C-1 の `memeGrowthMult` フィールドにも依存
参照必須: `docs/DESIGN_CROWDFUNDING.md`（仕様SSOT）全文 / `docs/DESIGN_AFFINITY_BATTLE.md` §1-3
関連: `KNOWLEDGE.md` §5（用語）

**用語**: キャラの兵力は**ミーム**（`soldiers` / 上限 `maxSoldiers`）。旧称 SP は廃止。**フィールド名は変更しない。**

---

## 0. 成功基準

達成するまでループして直すこと。

1. `npm run build` が成功する
2. クラファンは **`maxSoldiers >= 必要ミーム` のキャラのみ選択できる**（初回300）
3. 挑戦開始で参加キャラの **`maxSoldiers` が 0 になる**（`soldiers` も 0）
4. 挑戦終了時、成功・失敗を問わず **`maxSoldiers` = その回の必要ミーム、`soldiers` も同値まで満タン**
5. 2回目の必要ミームは 300、3回目は 600、4回目は 900（フィボナッチ）
6. **敵の編成人数がプレイヤーと一致する**（メイン1名なら敵もメイン1名）
7. **敵全撃破でゴール達成**。残ラウンドがあれば戦闘が続く
8. ゴール達成で参加キャラのパラメータが強化される
9. **ボーカルソフト化のゴールでのみ `charSong` が上がる**
10. 浅層探索は**ミームを消費しない**。敵は対称化されず、クラファンより弱い
11. 浅層探索の報酬でミームと好感度（+1）が増える。クラファンは好感度 +2
12. **ダンジョンでアイテムが手に入らない**（インベントリ件数が不変）

## 1. 敵プール（`dungeons.json` の作り替え）

**既存 `dungeons.json` を作り替える。** クラファン用と浅層探索用の2プールを持たせる。

現状は `dungeons[0].floors[].enemy` に1体ずつ固定データ（`name` / `charHp` / `charAttack` / `soldiers` / `soldierAtk` / `soldierDef`）。これを**プール（配列）**に変える。

- クラファン用プール
- 浅層探索用プール（**クラファンより弱くする**）

**データはすべて仮置きでよい。** 既存の龍泉洞5フロアの敵を流用・改変して構わない。

`App.jsx:43-68` の `buildDungeonEnemy(enemy)` は1体変換の関数。**複数体に対応させる**こと。

### 1-1. 抽選と対称化

| | クラファン | 浅層探索 |
|---|---|---|
| 抽選 | プールからランダム | プールからランダム |
| 人数 | **プレイヤーと対称**（メイン・サブとも同数） | **対称化しない** |

**対称化はクラファンのみ。** 通常戦闘（拠点攻撃・防衛）にも適用しない。

### 1-2. ボス戦

**何戦かに1度、選出数を増やす代わりにステータス倍率をかける**（ボスらしさの演出）。頻度・倍率は仮置きでよい。通常は選出数を増やす方式。

## 2. クラファン挑戦

### 2-1. 必要ミームとコスト

**没収されるのは `soldiers`（現在値）ではなく `maxSoldiers`（ミーム上限）。**

```
挑戦開始   maxSoldiers = 0  → soldiers も 0
   ↓
挑戦中     ミームを持たない状態で戦う。将軍本体（charHp）のみが戦力
   ↓
挑戦終了   成功・失敗を問わず maxSoldiers = その回の必要ミーム
           soldiers も同値まで満タン
```

**参加条件は `maxSoldiers >= 必要ミーム`。** `soldiers`（現在値）では判定しない。

**必要ミームはフィボナッチ**（キャラごとの挑戦回数で決まる）。

| 挑戦回数 | 1 | 2 | 3 | 4 | 5 | 6 | … |
|---------|---|---|---|---|---|---|---|
| 必要ミーム | 300 | 300 | 600 | 900 | 1500 | 2400 | … |

挑戦回数に上限はない。

### 2-2. 挑戦回数の記録

**`char` フィールドに持たせる**（例 `cfChallengeCount`、初期値0）。キャラ単位の値であり、セーブの `characters` 配列に自然に乗る。

`serializeState` / `deserializeToState` に追加し、**`SAVE_VERSION` を繰り上げる**（C-1 で 11 にしていれば 12）。旧セーブには `0` を補填。

### 2-3. ゴール（7種）

**達成条件は全種「敵全撃破」。** 種別は報酬の違いのみ。

**今後増える前提でハードコードせず、レジストリで解決すること。**

| ゴール種別 | 固有の報酬 |
|-----------|-----------|
| **ボーカルソフト化** | **`charSong`（歌）。この種別のみ** |
| **読み上げソフト化** | 本体パラメータ強化 |
| スタンプラリー | `memeGrowthMult`（ミーム増加倍率） |
| ライブ | `memeGrowthMult` |
| グッズ制作 | `memeGrowthMult` |
| アニメ制作 | `memeGrowthMult` |
| ゲーム制作 | `memeGrowthMult` |

### 2-4. 報酬

**全ゴール共通**で以下を強化する。上表の固有分はこれに加算される。

| 区分 | フィールド |
|------|-----------|
| 本体 | `charHp` / `charAttack` / `charDefense` / `attackCount` |
| ミーム | `soldierAtk` / `soldierDef` |

**`charSong` はボーカルソフト化でのみ上昇。** 共通強化には含めない。

`memeGrowthMult` は C-1 で新設したフィールド（ミーム上限成長の倍率）。増加幅は仮置きでよい。

**上昇量はすべて仮置き。1箇所にまとめること。**

### 2-5. ストレッチゴール

敵全撃破後、残ラウンドがあれば**追加の敵と戦闘を継続**し、ラウンド切れまで戦える。追加報酬あり（内容は仮置き）。

## 3. 浅層探索

クラファンと**同じ導線・同じフォーマット**。パラメータのみ異なる。

| 項目 | 仕様 |
|------|------|
| コスト | **なし**（`maxSoldiers` は減らない） |
| 参加条件 | 制限なし |
| 敵 | 浅層探索用プールから抽選。**対称化しない**・弱い |
| 終了条件 | ラウンド切れ（20ラウンド。C-2 実装済） |
| 報酬 | **ミーム** ＋ 同行キャラとの**好感度 +1** |

ミーム報酬量は仮置き（少なめ）。

### 3-1. アイテム報酬の廃止（P1積み残しの解決）

P1 で「ダンジョン `rewardItem` 付与停止」が計画されながら未実施のまま残っている。

```js
// DungeonScene.jsx:53-66 → GameContext.jsx:380 で inventory に追加され続けている
const rewardItemId = floorData?.rewardItemId ?? null;
const rewardItem = rewardItemId ? { instanceId: ..., itemId: rewardItemId } : null;
setLastRewardItem(rewardItem);
```

アイテム画面のUI経路は削除済みのため、取得物は閲覧不能のまま蓄積している。

**`rewardItem` の生成を停止し `@deprecated` コメントを付ける。** 獲得演出（`setLastRewardItem` を使う表示）も撤去する。

`dungeons.json` の `rewardItemId`、`items.json`、`ItemSystem.js`、`state.inventory` は**内部温存原則どおり残置**（削除しない）。

## 4. 好感度

`docs/DESIGN_AFFINITY_BATTLE.md` §1-3 に従う。

| 経路 | 加算 |
|------|------|
| クラファン挑戦（同行） | **+2** |
| 浅層探索（同行） | **+1** |

Phase A 実装済みの `gainAffinity(affinity, pairs, amount)` と `allPairs`（`src/game/utils/Affinity.js`）を**そのまま使う**。新規ユーティリティを作らないこと。

加算対象は参加キャラの全ペア。モブ（`_isMobInstance`）は除外。

## 5. やらないこと

- `_calcPool` 撤去・ミーム上限成長・`memeGrowthMult` の新設 → **C-1**
- ダンジョン基盤（入口・複数キャラ・ラウンド累積・休憩）→ **C-2**
- UI の「SP」→「ミーム」文字列置換 → 別タスク（`KNOWLEDGE.md` §16）
- 敵側の固定好感度 → 後回し
- UI の作り込み → 当面は暫定でよい

**指示範囲外のコード・コメントを変更しないこと。**
