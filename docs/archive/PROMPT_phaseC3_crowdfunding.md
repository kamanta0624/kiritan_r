# PROMPT_phaseC3_crowdfunding — クラファン挑戦と浅層探索（Phase C-3）

対象: ClaudeCode
前提: **C-2（ダンジョン基盤改修）完了後に着手すること**
参照必須: `docs/DESIGN_CROWDFUNDING.md`（仕様SSOT）/ `docs/DESIGN_AFFINITY_BATTLE.md` §1-3（好感度の加算量）

---

## 0. 成功基準

達成するまでループして直すこと。

1. `npm run build` が成功する
2. BottomBar から**クラファン挑戦**と**浅層探索**の2つに入れる
3. クラファン挑戦は**ミーム（`soldiers`）が 300 以上のキャラのみ選択できる**
4. クラファン挑戦を開始すると、参加キャラの `soldiers` が **0 になる**（全額没収）
5. ゴール達成で参加キャラが強化される
6. **ゴール未達成で強制帰還した場合、ミームは戻らない**
7. 浅層探索は**ミームを消費しない**
8. 浅層探索の報酬で**ミームと好感度が増える**（同行ペアに +1）
9. クラファン挑戦の同行ペアに好感度 **+2** が入る
10. **ダンジョンでアイテムが手に入らない**（インベントリ件数が不変）

## 1. 2つのモードの違い

同じダンジョンフォーマット（C-2 で作った基盤）を、パラメータ違いで2用途に使う。

| | クラファン挑戦 | 浅層探索 |
|---|---|---|
| 参加条件 | `soldiers >= 300`（仮置き定数） | 制限なし（`soldiers = 0` でも可） |
| コスト | **開始時に `soldiers = 0`**（全額没収） | **なし** |
| タイムリミット | 40ラウンド（C-2 で実装済） | 同上でよい |
| ゴール | あり。達成でキャラ強化 | なし（軽い探索） |
| 報酬 | ゴール報酬 ＋ 好感度 **+2** | ミーム ＋ 好感度 **+1** |
| 失敗時 | ミーム完全損失 | 損失なし |

## 2. クラファン挑戦

### 2-1. 参加条件とコスト

- 選択可能なのは `soldiers >= 300` のキャラのみ（**定数。1箇所にまとめること**）
- 挑戦開始時に参加キャラ全員の `soldiers = 0`
- ゴール未達成で帰還してもミームは戻らない

### 2-2. ゴール

`dungeons.json` の各定義に `goal: { type, condition }` を持たせる。

`type` は6種（`software` / `stamp_rally` / `live` / `goods` / `anime` / `game` 等、命名は任意）。**現時点では6種すべて同じ効果**とし、種別はフレーバーのみ。

**報酬ハンドラをレジストリで解決する形にすること**（効果をハードコードしない）。将来種別ごとに効果を分ける余地を残す。

達成条件は最深部到達（既存の `dungeonProgress.isFullyCleared`）でよい。

### 2-3. 報酬

**挑戦したキャラの強化。** 具体的な効果は「同一効果であればよい」ため、`maxSoldiers` 加算・能力値加算などから選んで実装してよい。**選んだ内容をコメントに明記すること。**

### 2-4. 早期達成後の追加戦闘

ゴール達成後、残ラウンドがあれば追加の敵と戦える。**敵は仮置きでよい**（既存フロアの敵の使い回しで可）。追加報酬の内容も仮置きでよい。

## 3. 浅層探索

### 3-1. 報酬

| 報酬 | 内容 |
|------|------|
| ミーム | `soldiers` を増やす（量は少なめ。定数でよい） |
| 好感度 | 同行キャラの全ペアに **+1** |

### 3-2. アイテム報酬の停止（P1積み残しの解決）

**P1（UI削除フェーズ）で計画されながら未実施だった項目。**

```js
// src/scenes/DungeonScene.jsx:53-66
const rewardItemId = floorData?.rewardItemId ?? null;
const rewardItem = rewardItemId ? { instanceId: ..., itemId: rewardItemId } : null;
setLastRewardItem(rewardItem);
... dungeonFloorClear({ ..., rewardItem })
// → GameContext.jsx:380 で inventory に追加されている
```

アイテム画面のUI経路は P1 で削除済みのため、**取得物は閲覧不能のまま蓄積している**。

**`rewardItem` の生成を停止し、`@deprecated` コメントを付ける。** 獲得演出（`setLastRewardItem` を使う表示）も併せて撤去すること。

`dungeons.json` の `rewardItemId`、`items.json`、`ItemSystem.js`、`state.inventory` は**内部温存原則どおり残置**（削除しない）。

## 4. 好感度の加算

`docs/DESIGN_AFFINITY_BATTLE.md` §1-3 の加算量に従う。

| 経路 | 加算 |
|------|------|
| クラファン挑戦（同行） | **+2** |
| 浅層探索（同行） | **+1** |

Phase A で実装済みの `gainAffinity(affinity, pairs, amount)`（`src/game/utils/Affinity.js`）と `allPairs` をそのまま使う。**新規のユーティリティを作らないこと。**

加算対象は参加キャラの全ペア。モブ（`_isMobInstance`）は除外。

---

## 5. やらないこと

- 敵編成の対称化・SP上限成長 → **C-1**
- ダンジョン基盤（入口・複数キャラ・ラウンド累積・休憩）→ **C-2**
- ゴール種別ごとの効果分岐 → 現時点では全種同一
- `dungeons.json` へのコンテンツ追加 → 既存1件で動けばよい
- UI の作り込み → 当面は暫定でよい
- 敵側の固定好感度 → 後回し

**指示範囲外のコード・コメントを変更しないこと。**

---

## 6. 注意

- ミーム閾値 300 / 好感度 +2・+1 / 浅層探索のミーム報酬量は、**すべて仮置きの定数**。後で調整するため1箇所にまとめること
- 投機的実装・不要な抽象化をしないこと
- 不明点があれば勝手に判断せず確認すること
