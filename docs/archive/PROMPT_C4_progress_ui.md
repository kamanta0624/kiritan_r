## 0. QA 指摘（実機確認で判明）

1. **クラファンが1戦でゴールになる。** 想定と違う
2. **報酬が表示されないためわかりづらい**

原因は `App.jsx:575` の `const isGoalWave = waveIndex === 1;`。**1波目を倒せばゴール**という実装になっている。仕様側の記述（旧「敵全撃破」）が曖昧だったため、進捗ポイント制へ改訂した。

## 1. 成功基準

達成するまでループして直すこと。

1. `npm run build` が成功する
2. **1戦倒しただけではゴールにならない**
3. 敵を倒すたびに進捗が加算され、**画面に % で表示される**
4. **進捗100%でゴール達成**、報酬が入る
5. 100%到達後も戦闘が続き、**200% / 300% と累積**してストレッチ報酬が入る（進捗はリセットしない）
6. **戦闘結果画面に増えたパラメータの一覧が具体値で出る**（`charHp +30` `charAttack +8` 等）。「参加キャラが強化された」のような文言のみは不可
7. 参加人数が増えると必要進捗ポイントが増える（1名 → 4名で約4倍）
8. 挑戦回数が増える（必要ミームが増える）と必要進捗ポイントが増える
9. 強いキャラで挑戦すると上位 tier の敵が出やすくなる

実機での確認まで行うこと。

## 2. 進捗ポイント制

### 2-1. 基本

| 項目 | 仕様 |
|------|------|
| 加算 | 敵を**1体撃破するごと**に、その敵の `progressPoint` を加算 |
| ゴール | 進捗が**必要進捗ポイントに到達**したら達成（＝100%） |
| ストレッチ | **累積型**。200% / 300% と積み上がり、100%刻みで追加報酬 |
| 進捗リセット | **しない** |

### 2-2. 必要進捗ポイント

**必要ミーム × 参加人数** に比例させる。係数は仮置きで `crowdfundingConfig.js` に置くこと。

```
必要進捗ポイント = 必要ミーム（その回の値） × 参加人数 × 係数
```

- 挑戦回数が増える → 必要ミームが増える → ゴールが遠のく
- 参加人数が増える → ゴールが遠のく（報酬も人数分増えるため釣り合う）

### 2-3. 敵の定義に追加

`dungeons.json` の敵定義に2フィールドを足す。

| フィールド | 内容 |
|-----------|------|
| `tier` | 強さ帯（例 1〜3）。抽選確率の制御に使う |
| `progressPoint` | 撃破時に加算される進捗ポイント。**強い敵ほど高く**する |

既存の `crowdfundingPool` / `shallowPool` の全エントリに付与する。**値はすべて仮置きでよい。**

### 2-4. 敵の強さ抽選

**プレイヤー側が強いほど、上位 tier の敵が出る確率を上げる。**

強さの指標は以下の**併用**。

| 指標 | 取り方 |
|------|--------|
| 本体パラメータ合計 | 参加キャラの `charHp` / `charAttack` / `charDefense` / `soldierAtk` / `soldierDef` などの合計 |
| 必要ミーム | その回の必要ミーム（過去の挑戦回数の代理） |

**`maxSoldiers` は使えない。** クラファン挑戦中は 0 になるため。

判定式・確率テーブルは仮置きでよい。`crowdfundingConfig.js` に集約すること。

浅層探索は**対称化も強さ連動もしない**（従来どおりランダム抽選）。

## 3. UI 改善

### 3-1. 進捗表示

**現在の進捗を % で常時表示する。** `DungeonShell`（残ラウンド表示の近く）が想定位置。

- 100%を超えたら `240%` のように累積値を出す
- 浅層探索には進捗の概念が無いため表示しない

### 3-2. 報酬表示

**戦闘結果画面（`wave_result`）で、増えたパラメータを具体値の一覧で出す。**

現状は文言のみで何が増えたか分からない。

```
// 現状（不可）
'参加キャラが強化された'

// 期待
東北きりたん
  charHp +30 / charAttack +8 / charDefense +8 / attackCount +1
  soldierAtk +10 / soldierDef +10 / charSong +10
```

`applyGoalReward` / `applyStretchReward` / `applyShallowReward` が内部で計算している delta を**呼び出し元へ返し、画面に渡す**こと。表示形式は暫定でよいが、**フィールド名と増加量が読み取れること**。

キャラごとに分けても、全員共通なら1回だけ出してもよい。

### 3-3. ゴール到達演出

進捗が100%（および200%・300%…）に到達した戦闘の結果画面で、**達成を明示する**。

## 4. やらないこと

- ダンジョン基盤（入口・複数キャラ・ラウンド累積・休憩）→ C-2 で完了済
- ミーム上限の没収・返還ロジック → C-3 で完了済。**触らない**
- 好感度の加算 → C-3 で完了済。**触らない**
- UI の作り込み・デザイン調整 → 当面は暫定でよい
- `SAVE_VERSION` の繰り上げ → **不要**（進捗はセッション内の値でセーブ対象外）

**指示範囲外のコード・コメントを変更しないこと。**

- 投機的実装・不要な抽象化をしないこと
